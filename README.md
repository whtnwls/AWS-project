# 요즘.zip

> 요즘 다들 무슨 얘기해?
>
> 요즘 주목받는 밈·유행어와 음식·디저트를 한곳에서 둘러보고, **무엇인지**와 **왜 화제인지** 쉽게 이해할 수 있는 트렌드 웹입니다. 궁금한 표현을 직접 찾는 검색 기능도 제공합니다.

AWS 부트캠프 해커톤용 **프로토타입**입니다. 완성형 시스템이 아니라, 사용자가 겪는 불편과 이 서비스가 그것을 어떻게 해결하는지 보여주는 데 집중했습니다.

---

## 이 서비스가 푸는 문제

주변 유행(밈·유행어, 음식·디저트)을 몰라 대화 맥락을 놓치는 사람들이 있습니다.
친구·자녀·방송에서 나온 표현을 매번 물어보기는 머쓱하고, 직접 검색하면 여러 글을 읽어야
의미와 화제가 된 이유를 겨우 파악할 수 있습니다. 무엇이 유행하는지 모르면 애초에
무엇을 검색해야 할지도 모릅니다.

**핵심 문제: "요즘 이야기되는 것을 쉽게 발견하고, 그 의미와 화제가 된 이유를 빠르게 이해하기 어렵다."**

### 화면이 문제를 푸는 방식

- **홈** — 검색창보다 트렌드 카드가 먼저 보이게 배치해, 무엇을 검색할지 모르는 사용자도 바로 둘러보며 발견합니다. 카테고리 필터(전체 / 밈·유행어 / 음식·디저트)로 탐색 부담을 줄입니다.
- **트렌드 카드** — 이름, 카테고리, 쉬운 설명 한 줄, 주목 이유 한 줄만 담아 스크롤만으로 감을 잡게 합니다.
- **상세 페이지** — 별칭, 쉬운 소개, 주목 이유, 출처/확인일을 공통으로 두고, 밈은 뜻·뉘앙스·사용 예시를, 음식은 특징을 더해 한 페이지에서 맥락을 완결합니다.
- **검색** — 이름·별칭으로 바로 찾고, 결과가 없으면 안내 문구와 전체 목록 복귀 버튼을 제공합니다.

## 기술 스택

- React 18 + TypeScript + Vite
- react-router-dom (홈 / 상세 라우팅)
- 데이터: 정적 TypeScript 데이터 1개 (`src/data/trends.ts`) — DB·API·로그인 없음
- 검색·필터: 전부 프런트엔드에서 처리

## 로컬 실행

사전 요구: Node.js 18 이상 (개발은 Node 24에서 확인했습니다)

```bash
npm install
npm run dev
```

터미널에 표시되는 주소(기본 http://localhost:5173)를 브라우저로 엽니다.

### 그 외 명령

```bash
npm run build    # 타입 검사(tsc) + 프로덕션 번들(dist/)
npm run preview  # 빌드 결과물 미리보기
npm run lint     # 타입 검사만 (tsc --noEmit)
```

## 시연 순서 (대표 시나리오)

1. **홈 진입** — 검색창과 함께 '이번 주 주목할 트렌드' 카드가 먼저 눈에 들어옵니다.
2. **몰랐던 음식 발견** — 예: `두바이 초콜릿` 또는 `탕후루` 카드를 클릭합니다.
3. **상세 확인** — 무엇인지(소개·특징)와 왜 화제인지, 출처·확인일을 봅니다.
4. **밈 둘러보기** — 홈으로 돌아와 `밈·유행어` 필터를 눌러 카테고리를 전환합니다.
5. **검색** — 전에 들어본 표현(예: `중꺾마`, `꾸안꾸`)을 검색창에 입력하면 즉시 결과가 나오고, 카드를 눌러 뜻과 사용 예시를 확인합니다.
6. **빈 결과 처리** — 없는 단어를 검색하면 안내 문구와 '전체 목록 보기' 버튼이 나타납니다.

## 콘텐츠 주의사항 (중요)

- 현재 들어 있는 트렌드는 **데모(예시) 데이터**입니다. 실제 유행 여부를 확인한 자료가 아니며, UI에도 '예시 · 데모 데이터'로 표시됩니다.
- **출처(source)와 확인일(checkedAt)은 지어내지 않았습니다.** 안내 문구만 들어 있으니, 실제 발표 시 팀이 확인한 출처와 날짜로 교체하세요.
- 밈의 **사용 예시는 실제 인용이 아닌 '예문'** 이며, 상세 페이지에서 명확히 구분 표시됩니다.

### 실제 발표 자료로 바꾸기

`src/data/trends.ts`의 배열 항목만 교체하면 됩니다. 화면 코드는 수정할 필요가 없습니다.

- 공통: `name`, `aliases`, `category`(`"meme"` 또는 `"food"`), `emoji`, `shortDescription`, `whyNow`, `intro`, `source`, `checkedAt`, `isDemo`
- 밈(`meme`): `meaning`, `usageExample`
- 음식(`food`): `whatItIs`, `features`(문자열 배열)

실제로 확인한 자료라면 `isDemo: false`로 바꾸고, `source`·`checkedAt`에 확인한 출처와 날짜를 넣으면 '데모 데이터' 표시가 사라집니다.

## AWS Amplify Hosting 배포

이 프로토타입은 AWS Amplify Hosting으로 배포할 수 있도록 구성되어 있습니다.
빌드 설정은 저장소의 [`amplify.yml`](./amplify.yml)에 들어 있습니다.

> 참고: 아래는 배포 **방법 안내**입니다. 아직 실제 AWS 리소스에 연결되어 있지 않습니다.

### 배포 절차 (Git 연동 방식)

1. 이 저장소를 GitHub/GitLab/Bitbucket 등 Git 공급자에 올립니다.
2. AWS 콘솔에서 **AWS Amplify** → **New app** → **Host web app**을 선택합니다.
3. Git 공급자와 이 저장소/브랜치를 연결합니다.
4. 빌드 설정은 저장소의 `amplify.yml`을 자동 인식합니다. (빌드 산출물 디렉터리: `dist`)
5. **Save and deploy**를 누르면 빌드 후 배포됩니다.

### SPA 라우팅 리라이트 (필수)

이 앱은 클라이언트 라우팅을 사용하므로, `/trend/두바이-초콜릿` 같은 경로를 새로고침하거나
직접 열면 Amplify가 404를 반환할 수 있습니다. 이를 막으려면 Amplify 콘솔에서
**App settings → Rewrites and redirects**에 아래 규칙을 추가하세요.

| Source address | Target address | Type |
| --- | --- | --- |
| `/<*>` | `/index.html` | `200 (Rewrite)` |

(정식 명칭은 "Redirects for single page web apps (SPA)" 규칙입니다. Amplify 문서의 SPA 안내에 동일한 규칙이 예시로 제공됩니다.)

### 로컬 빌드 산출물 직접 올리기 (대안)

Git 연동 없이 테스트하려면 로컬에서 빌드한 `dist` 폴더를 Amplify의 수동 배포(drag & drop)로 올릴 수도 있습니다.

```bash
npm run build   # dist/ 생성
```

이 경우에도 위의 SPA 리라이트 규칙은 동일하게 추가해야 합니다.
